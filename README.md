# Вертипорты Москвы · eVTOL — демо-панель мониторинга

Учебный проект **КОНТУР Н · P01 «Городской мультимодальный вертипорт» · трек 04 «Цифровые системы и управление»** (НИУ МГСУ).

Интерактивная 3D-карта Москвы с узлами вертикального транспорта и симуляцией полётов eVTOL. Все природные и эксплуатационные параметры меняются на панели. Система реагирует на них по цепочкам «данные → анализ → решение → действие» **C1–C13** с листа А2 трека 04.

> Все узлы — учебные предложения для анализа, а не действующие или утверждённые вертипорты. Запретная зона над центром условная. Пороги решений имеют статус «И» и ждут данных от треков 05 и 06.

## Запуск

```bash
npm install
npm run dev      # http://localhost:3200 (разработка)
```

Продакшн на своём сервере:

```bash
npm run build
npm start        # порт 3200
```

или через Docker:

```bash
docker build -t vertiport-dashboard .
docker run -d -p 3200:3200 --name vertiport vertiport-dashboard
```

После этого панель доступна по ссылке `http://<адрес-сервера>:3200`.

|---|---|---|
| Среда | направление ветра | стрелка на компасе |
| | скорость ветра и порывы | ползунки, м/с |
| | температура | ползунок, °C |
| | осадки | переключатель: нет / дождь / снег / ледяной дождь, плюс интенсивность |
| | видимость, нижняя граница облаков | ползунки |
| | обогрев площадок | тумблер |
| Пороги «И» | ветер: ограничение и закрытие, мин. видимость, мин. облачность | ползунки |
| Эксплуатация | режим O1 / O2 / O3 (4 / 8 / 12 оп/ч на FATO) | переключатель |

| | мощность зарядного места, энергетический резерв | ползунки |

| Узел | люди в зоне, пожар/АКБ, отказ питания, закрытие диспетчером | тумблеры |

## Цепочки решений

| Код | Данные → решение |
|---|---|
| C1 | ветер, видимость, облачность → площадка открыта / ограничена / закрыта; борт с порывом выше своего предела уходит на запасную |
| C2 | температура + осадки → обогрев покрытия или закрытие (ледяной дождь — всегда закрытие) |
| C3 | занятость FATO, статус узла → допуск к посадке или holding, после 15 мин — запасная площадка |
| C4 | ветер по курсу → путевая скорость и ETA |
| C5 | курс → эшелон (восток — чётные уровни, запад — нечётные), обход запретной зоны |
| C6 | интенсивность O1–O3 → лимит операций в час, заполнение стоянок |
| C7 | заряд аппаратов, число зарядных мест → очередь зарядки |
| C8 | мощность сети → ограничение зарядки; отказ питания |
| C11 | люди или предметы в зоне → запрет взлёта и посадки |
| C12 | пожар / перегрев АКБ → аварийный режим, все уходят на запасные |
| C13 | статистика → журнал решений |

## Модели аппаратов

`src/lib/models.ts`. Источник: база знаний КОНТУР Н «Классы низковысотных воздушных судов» (места, МВМ, габарит D, дальность, класс НВ·Д). ECOLIBRI — АО «Эколибри» и [AeroNet](https://drones.aeronet2035.ru/model/914/). Крейсерская скорость, предельный ветер и ёмкость батареи — рабочие допущения (статус «Р»), в карточке модели они перечислены в `assumed`.

3D-модели строятся кодом (`src/lib/meshes.ts`): квадрокоптер (груз), мультикоптер (EHang, Volocopter), eVTOL с крылом (Joby, Archer, Eve, CityAirbus, ECOLIBRI, Samad).

## Архитектура

- **Next.js + MapLibre GL + deck.gl 9** — стек взят из [Aeris](https://github.com/kewonit/aeris).
- **Подложка** — [OpenFreeMap](https://openfreemap.org) (OSM, без ключей), 3D-здания по высотам из OSM. Для работы без внешних сервисов карту можно заменить своими PMTiles.
- **Источник трафика заменяемый** (`src/lib/source.ts`): сейчас `SimSource` (симулятор в браузере). Для реальных данных пишется `WsSource`: WebSocket с нашего сервера, куда идут телеметрия eVTOL и датчики. Карта и панели при этом не меняются.

```
src/
  app/            страница Next.js
  components/     Dashboard (экран), MapView (карта), layers (слои deck.gl), Controls (компас, ползунки)
  lib/            models, vertiports, params, sim (симулятор и цепочки C1–C13), source, meshes, geo
```
